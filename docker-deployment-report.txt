============================================================
1. PROJECT OVERVIEW
============================================================

CodeCruncher is a React + TypeScript + Vite web application.

The application was containerized using Docker and served through
Nginx. Docker Compose was used to deploy the application together
with PostgreSQL. The Docker image was pushed to Amazon ECR and
deployed to Amazon ECS using AWS Fargate.

25. PROBLEMS ENCOUNTERED
============================================================

Problem 1:
Docker container name already existed.

Error:

Conflict. The container name was already in use.

Solution:

docker rm -f codecruncher-container


Problem 2:
Port 8080 was already allocated.

Error:

Bind for 0.0.0.0:8080 failed:
port is already allocated

Solution:

The existing container using port 8080 was stopped and removed.

Commands:

docker stop codecruncher-container
docker rm codecruncher-container


Problem 3:
VITE_SUPABASE_URL environment variable warning.

Solution:

The Compose configuration was reviewed and build arguments were
removed where they were not consumed by the Dockerfile.


Problem 4:
Docker Compose buildx warning.

The available Docker Compose installation used the classic build
process successfully, and the image was created successfully.

27. SECURITY CONSIDERATIONS
============================================================

1. Do not commit .env files to GitHub.
2. Do not expose database port 5432 publicly.
3. Use IAM roles instead of hard-coded AWS credentials.
4. Restrict EC2 and ECS Security Group rules.
5. Use HTTPS for production deployments.
6. Store secrets in AWS Secrets Manager or Parameter Store.
7. Enable ECR image scanning.
8. Keep Docker base images updated.
9. Use versioned Docker image tags.
10. Apply least-privilege IAM policies.


============================================================
28. RESOURCE OPTIMIZATION
============================================================

1. Multi-stage Docker builds reduce runtime image size.
2. Nginx provides a lightweight production runtime.
3. Use npm ci for reproducible builds.
4. Remove unused Docker images and containers.
5. Apply ECR lifecycle policies.
6. Monitor Fargate CPU and memory usage.
7. Configure ECS auto scaling when application traffic increases.
